Lilith Architecture

This repository contains the public architecture and research notes behind my first large-scale software engineering project.

What started as a small football modelling experiment slowly evolved into a replayable event-driven decision system with:

- replay infrastructure
- time-safe validation
- calibration pipelines
- governance layers
- fail-closed architecture
- shadow deployment flows
- staged rollout logic
- audit and recovery tooling

The purpose of this repository is not to expose a “winning model”, but to document the engineering and architectural side of the system.

I’m sharing parts of the project to:

- receive feedback from more experienced developers
- understand architectural mistakes
- identify overengineering risks
- improve validation and governance
- learn better software engineering practices

Most production logic, thresholds, private datasets and deployment configurations are intentionally excluded.

---

Why I Built This

This is my first serious programming project.

I started with almost no software engineering background and used this project to learn:

- orchestration
- probabilistic systems
- replay pipelines
- temporal validation
- ML governance
- fail-safe design
- audit tooling
- large-scale project organization

Over time, the project became much larger than originally expected and evolved into a multi-stage experimental platform.

Current Focus

The current research focus is centered around:

- replayable season-by-season evaluation
- event-first modelling
- anti-leakage validation
- calibration stability
- governance and safety layers
- deployment architecture
- shadow/live comparison systems
